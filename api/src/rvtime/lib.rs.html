1//! A RISC-V compiler with a wasmtime-like interface.
2//!
3//! Load a statically linked RV64IMAC ELF, compile it to native code with
4//! Cranelift, call its exported functions from Rust, and let it call back.
5//!
6//! ```no_run
7//! use rvtime::{Caller, Config, Engine, Linker, Module, Store};
8//!
9//! # fn main() -> anyhow::Result<()> {
10//! let engine = Engine::new(&Config::default())?;
11//! let module = Module::from_file(&engine, "guest.elf")?;
12//!
13//! let mut store = Store::new(&engine, 0u64);
14//! let mut linker = Linker::new(&engine);
15//!
16//! // The guest reaches this with `ecall` and `a7 == 1`.
17//! linker.func_wrap(1, |mut caller: Caller<'_, u64>, a: u64, b: u64| {
18//!     *caller.data_mut() += 1;
19//!     Ok(a + b)
20//! })?;
21//!
22//! let instance = linker.instantiate(&mut store, &module)?;
23//! let add = instance.get_typed_func::<(u64, u64), u64>("op_add")?;
24//! assert_eq!(add.call(&mut store, (10, 3))?, 13);
25//! # Ok(())
26//! # }
27//! ```
28//!
29//! ## How this differs from wasmtime
30//!
31//! - **Host functions are keyed by number, not name.** A guest calls them with
32//!   `ecall`, taking the number from `a7`. An ELF has no symbolic import table
33//!   to resolve names against.
34//! - **A store holds one instance.** A program image is one address space and
35//!   one register file; there is nothing to gain from sharing a store.
36//! - **Signatures are not checked.** Arguments are plain 64-bit words in
37//!   `a0`..`a7`, so the type parameters on
38//!   [`get_typed_func`](Instance::get_typed_func) choose how many registers to
39//!   use rather than describing something the guest declared.
40//!
41//! ## Guest memory
42//!
43//! Each store reserves a guest address space of
44//! [`Config::memory_size`](Config::memory_size) bytes — 64 MiB by default. The
45//! reservation is lazy, so an unused tail costs address space rather than
46//! resident memory, but it is still per-store address space, which matters when
47//! many guests run at once.
48//!
49//! The size must be a power of two. Guest addresses are confined by masking
50//! with `memory_size - 1`, which is what keeps a program inside its own memory;
51//! any other size would leave part of the mask's range pointing past the
52//! reservation. The mask is compiled into the code, so a [`Module`] is tied to
53//! the size its [`Engine`] was configured with, and a [`Store`] always maps at
54//! the module's size.
55//!
56//! One consequence worth knowing: confinement is not a precise bounds check. An
57//! address past the end of the space wraps and may land on a mapped page rather
58//! than faulting. The guest still cannot reach anything outside its own memory.
59//!
60//! The space is laid out as:
61//!
62//! ```text
63//! [ image ][ heap ][ guard ]        ...        [ stack ]
64//! 0                                                size
65//! ```
66//!
67//! The heap is committed read-write and zeroed, and is what a guest allocator
68//! manages. rvtime does not carve it up or hand it to the guest: read the
69//! bounds with [`Store::heap`] and pass them in however your host interface
70//! prefers — a host function you register, or arguments to an init export.
71//! Committing it costs address space rather than memory, since pages are
72//! faulted in only when touched.
73//!
74//! ## Guest requirements
75//!
76//! The image must be a statically linked RV64IMAC ELF **linked with
77//! `--emit-relocs`**. The relocations are what identify which functions have
78//! their address taken, and therefore where an indirect call may legally land.
79//! Without them a computed jump has no way to be checked.
